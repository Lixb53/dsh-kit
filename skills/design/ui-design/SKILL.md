# UI 设计

关注的是「看起来像认真设计过」，而不是「能跑就行」。所有视觉决策必须有依据：来自既有设计系统、品牌规范，或方向卡里显式声明的假设。

## 何时使用

- 产品方向已确定，需要视觉风格、配色、字体与组件规范。
- 需要把设计系统落到令牌与组件层。
- 前端实现完成，需要 UX / 可访问性审查。
- 界面「能用但不好看」，需要诊断与提升方案。

## 不适用

- 需求本身还没定义清楚 → `product-design`。
- 直接写业务代码 → `frontend-dev`。

## 输入

- 产品类型、目标用户、核心任务。
- 既有设计系统 / 品牌规范（存在时先完整读取，再写第一行 CSS）。
- 交付形态：页面、组件库、设计稿、可运行 HTML。
- 约束：必须沿用的品牌色、必须达到的 WCAG 等级。

## 工作流

### 第 1 步：方向卡（唯一视觉契约，锁定后不得漂移）

用不超过一页的篇幅定死七件事：

1. **风格定位**：极简 / Bento / 编辑感 / 玻璃拟态 / 大字排版 / 暗黑中性，必须选一个。
2. **色彩策略**：主色、中性阶、强调色使用规则；focus ring 用哪个色一次定死，全站同规格。
3. **字体与层级**：字阶数量、显示字与正文的对比方式、第二字体策略；声明哪个字号是全页唯一最大，且它必须对应核心任务。
4. **形状与间距**：圆角策略、间距基准网格；与实现不一致的取舍写「豁免 + 理由」。
5. **动效原则**：时长、触发条件、`prefers-reduced-motion` 降级方式，降级必须有替代指示。
6. **响应式策略**：断点、栅格、导航折叠方式、触控目标尺寸。
7. **差异化声明**：区别于 AI 默认审美的 3 处具体决策，各写理由。

写不出第 7 条，说明方向还没想清楚，回到第 1 条重选。

### 第 2 步：令牌

- 三层结构：Primitive → Semantic → Component，输出 DTCG JSON 与 CSS 变量。
- 语义令牌按用途命名（`surface` / `foreground` / `primary` / `danger` / `ring`），不按颜色命名。
- 暗色模式只换语义映射，不逐页调色。
- 每个组件状态（default / hover / active / focus / disabled / loading / error）都有令牌落点。

### 第 3 步：组件规范

每个组件写清：anatomy、变体、状态、尺寸、令牌映射、可访问性要求、禁忌用法。

- 破坏性操作使用 danger 语义，不得借用主色。
- loading 保持全强度并换 spinner，不借用 disabled 的降透明度。
- 图标按钮必须有可访问名称与最小 24×24 命中区。
- 不用 Emoji 充当结构性图标。

### 第 4 步：界面产出

- 主操作首屏可见；主次按钮有可感知对比。
- 交互元素齐备 hover / active / focus 三态，链接也要 `:active`。
- 异步动作有加载指示与防重复提交闭环。
- 错误提示包含下一步动作与示例值。
- 空状态给出下一步，而不是一句「暂无数据」。
- 中文界面遵守 `docs/cjk-typography.md`（字阶、行高、标点、系统字体栈）。

### 第 5 步：UX 审查（对实现）

四个维度独立打分，不取平均：

1. **方向一致性**：是否只遵循一个方向；方向卡每条规则是否有代码落点。
2. **层级与信息传达**：陌生人能否判断第一/第二/第三眼；最大字号是否对应最重要信息。
3. **执行完整度**：三态四态、错误可操作性、焦点管理、验收逐条。
4. **原创性**：差异化声明 3 条是否逐条兑现。

反 AI 默认审美硬信号（命中即扣分）：紫蓝渐变 hero、`#0D1117` 暗底配 gray-400 正文、Emoji 结构图标、卡片统一 `hover:scale-105`、`bg-clip-text` 渐变字、卡片套卡片、逐节三卡网格、无差别 fade-up、占位假数据、只做 happy path。

## 交付物

```
design/<feature>/
├── direction-card.md
├── tokens.json          # DTCG
├── tokens.css
├── components/<name>.md # 组件规范
├── prototype/index.html # 可运行
└── review.md            # UX 审查结论
```

## 验收门禁

- 方向卡七项齐全，差异化声明 3 条能落到具体选择。
- 令牌三层结构完整，组件状态有映射。
- 正文对比度 ≥ 4.5:1，大字 ≥ 3:1；focus 可见；键盘可达。
- 280px 到 1440px 无横向溢出；触控目标 ≥ 24×24。
- 审查结论逐条带证据（文件、选择器、令牌名），不写「建议优化」。

## 与其他角色的交接

- 给 `frontend-dev`：方向卡、令牌、组件规范、原型、验收标准。
- 前端实现偏离方向卡时：要么改实现，要么在方向卡写「豁免 + 理由」并请需求方确认。
- 评审只对声明过的契约打分；未声明的不作为扣分依据。

## 可配合的外部技能包

`ui-ux-pro-max`（风格/配色/字体检索）、`ux-ui-agent-skills`（DTCG 令牌、组件规格、52 道门禁）、`accessibility-agents`（WCAG 2.2 AA 审计）、`frontend-design`（审美方向）。见 [`docs/skill-catalog.md`](../../docs/skill-catalog.md)。
